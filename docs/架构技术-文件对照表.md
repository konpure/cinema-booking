# 架构技术 — 文件对照表

> 对照课程 PPT《可选用的架构技术》清单，说明本项目每种技术的**用途**、**是否已实现**、**对应源码/配置文件**。
>
> 说明：MySQL、HTML、CSS、Git 等不计入课程架构技术，本文档不列入。

## 一、已实现（答辩可演示）

### 1. Spring Security

|------|------|
| 用途 | JWT 无状态认证、角色权限（USER / ADMIN） |

| 登录/注册 | `backend/src/main/java/com/cinema/service/AuthService.java` |
| 接口 | `backend/src/main/java/com/cinema/controller/ApiControllers.java` → `AuthController` |

### 2. Redis（课程清单：Redis / Memcached 二选一）

| 项目 | 内容 |
|------|------|
| 用途 | 分布式座位锁（防超卖）、占座 TTL 自动释放 |
| 依赖声明 | `backend/pom.xml` → `spring-boot-starter-data-redis` |
| 连接配置 | `backend/src/main/resources/application.yml` → `spring.data.redis` |
| Redis 配置类 | `backend/src/main/java/com/cinema/config/RedisConfig.java` |
| 核心业务 | `backend/src/main/java/com/cinema/service/RedisSeatService.java` |
| 调用方 | `backend/src/main/java/com/cinema/service/BookingService.java` |
| 订单完成后释放锁 | `backend/src/main/java/com/cinema/service/OrderService.java` |
| 容器服务 | `docker/docker-compose.yml` → `redis` 服务 |
| 单元测试 | `backend/src/test/java/com/cinema/RedisSeatServiceTest.java` |

**可用性场景对应：** 场景 A 抢票高峰防超卖；场景 B 占座 TTL 超时自动释放。

---

### 3. MQ / RabbitMQ（课程清单：MQ、RabbitMQ / Kafka 二选一）

| 项目 | 内容 |
|------|------|
| 用途 | 下单请求异步削峰，订单持久化后由消费者处理 |
| 依赖声明 | `backend/pom.xml` → `spring-boot-starter-amqp` |
| 连接配置 | `backend/src/main/resources/application.yml` → `spring.rabbitmq` |
| 交换机/队列 | `backend/src/main/java/com/cinema/config/RabbitMQConfig.java` |
| 消息体 | `backend/src/main/java/com/cinema/mq/OrderMessage.java` |
| 生产者 | `backend/src/main/java/com/cinema/service/BookingService.java` → `submitOrder()` |
| 消费者 | `backend/src/main/java/com/cinema/mq/OrderConsumer.java` |
| 订单入库 | `backend/src/main/java/com/cinema/service/OrderService.java` → `createOrderFromMessage()` |
| 容器服务 | `docker/docker-compose.yml` → `rabbitmq` 服务 |
| 管理台 | 启动后访问 `http://<虚拟机IP>:15672`（guest/guest） |

**可用性场景对应：** 场景 A 削峰填谷；场景 B 消息持久化 + 消费重试（`application.yml` 中 `retry.max-attempts: 3`）。

### 5. 负载均衡（课程清单独立项）

| 项目 | 内容 |
|------|------|
| 用途 | 双 Spring Boot 实例分流，单实例故障时自动剔除 |
| 配置位置 | `docker/nginx/nginx.conf` |
| 关键配置 | `upstream cinema_backend` + `least_conn` |
| 后端实例 1 | `docker/docker-compose.yml` → `backend-1`（`SPRING_APPLICATION_NAME=cinema-backend-1`） |
| 后端实例 2 | `docker/docker-compose.yml` → `backend-2`（`SPRING_APPLICATION_NAME=cinema-backend-2`） |
| 验证接口 | `GET /api/health` → 返回 `"instance": "cinema-backend-1"` 或 `"cinema-backend-2"` |
| 健康检查实现 | `backend/src/main/java/com/cinema/controller/ApiControllers.java` → `HealthController` |

**可用性场景对应：** 场景 B 实例故障转移（`max_fails=2 fail_timeout=10s`）。
