# 影院订票系统 — 技术总结报告

## 一、项目概述

本项目为软件架构设计实践课程大作业，选题**影院订票系统**。系统实现了影片浏览、在线选座、异步下单、订单管理等核心业务流程，并通过多种架构技术保障系统在高峰流量和局部故障场景下的**可用性**。

## 二、业务场景与可用性设计

### 场景 1：热映影片开售抢票高峰

**问题分析：**
- 大量用户同时选座，数据库并发写入压力大
- 可能出现座位超卖
- 同步下单导致接口响应超时

**架构对策：**

| 对策 | 技术 | 说明 |
|------|------|------|
| 分布式座位锁 | Redis | `SETNX` + TTL 实现占座，防止超卖 |
| 削峰填谷 | RabbitMQ | 下单请求入队，异步消费创建订单 |
| 负载分担 | Nginx | `least_conn` 策略分发到 2 个后端实例 |
| 热数据缓存 | Redis | 锁定座位状态实时查询 |

### 场景 2：服务实例短时不可用

**问题分析：**
- 某个 Spring Boot 实例宕机导致部分请求失败
- 占座后若服务中断，可能导致座位长期被锁

**架构对策：**

| 对策 | 技术 | 说明 |
|------|------|------|
| 故障转移 | Nginx | `max_fails` + `fail_timeout` 自动剔除故障实例 |
| 消息可靠 | RabbitMQ | 持久化队列 + 消费重试（最多 3 次） |
| 占座超时 | Redis | 锁定 TTL 600 秒，过期自动释放 |
| 健康检查 | Actuator | `/actuator/health` 供 Nginx/运维探测 |

## 四、已实现架构技术

1. **Spring Security** — JWT 无状态认证，角色权限控制（USER/ADMIN）
2. **Redis** — 座位分布式锁，支持 TTL 自动过期
3. **RabbitMQ** — 订单异步处理，JSON 消息序列化
4. **Nginx** — 反向代理、静态资源、双实例负载均衡
5. **Docker Compose** — MySQL/Redis/RabbitMQ/双后端/Nginx 一键部署
6. **Vue 3** — 影院风格 SPA 前端
7. **ECharts** — 管理端票房柱状图、热门影片饼图
8. **SLF4J/Logback** — 统一日志格式，关键业务路径可追踪
9. **JUnit** — Redis 座位锁逻辑单元测试

## 六、核心流程

### 选座购票流程

1. 用户选择座位 → 调用 `/api/bookings/lock`
2. 后端 Redis 逐座 `SETNX` 加锁（10 分钟 TTL）
3. 用户确认 → 调用 `/api/bookings/submit`
4. 消息发送至 RabbitMQ → 消费者异步创建订单
5. 订单入库 → 释放 Redis 锁 → 前端跳转订单页

## 八、总结

本系统以影院订票为业务载体，围绕**可用性**核心质量属性，通过 Redis 并发控制、RabbitMQ 异步解耦、Nginx 冗余负载等架构手段，有效应对抢票高峰和实例故障两类典型场景，满足课程大作业对架构设计与技术集成的要求。
